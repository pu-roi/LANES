## Intended behavior

An authenticated administrator requests extraction for one already captured article. The backend copies its exact saved body, runs the retained location model, applies the separately labeled v40 combined proposals, then uses v41 to associate supported facts. It returns a temporary JSON preview. Normal discovery, durable processing, publication and routing continue through their existing paths.

For an article saying a road had half-knee flooding at 6 PM, a supported group can contain the road, source-exact depth, and a time labeled `observation`. Explicit flood-start wording can instead yield `onset`. Publication/report clocks never fill a missing observation clock. Unknown dates and timezones remain unknown. Subsided/cleared reports and their supporting times remain in the response; database retention and current-map filtering are later work.

## Backend contract and projection

- Add `POST /api/v1/admin/news/articles/{article_id}/ner-preview`, without a request body. Require the existing active-admin dependency, a positive article ID, `Cache-Control: no-store`, and the existing three-requests-per-minute limiter convention. Keep the route thin; use a dedicated service and Pydantic response models.
- Read the current `NewsArticle` once into an immutable input value. Extract only `article_text`, without trimming, Unicode normalization, title/excerpt concatenation or sentence relocation. Return its article ID, field identity, SHA-256 of UTF-8 body bytes, and a canonical input hash binding source identity, body and publication metadata. This is the body read for this request, not a claim to a persisted article-version ID. Do not create a version or extraction-run row.
- Return `schema_version`, source identity, pipeline provenance, original neural mentions, effective mentions, accepted rule proposals/abstentions, grouped fields, unassigned facts, the validated context graph and known limitations. Preserve all six location labels, source-exact offsets/text, fact/relation IDs, qualifiers and uncertainty. Report model/tokenizer/resource/code hashes and the actual image identity. Do not invent per-entity confidence.
- Make each group a lossless view of relations with the same exact target-occurrence set, relation scope and evidence spans. Order target IDs by source offsets and evidence by offset before grouping. Carry arrays of depth, time, status and access facts, with IDs/evidence on each item; empty arrays mean no attached extraction. Different source occurrences or evidence spans remain separate groups even if names match. No new event resolution, city-parent inference or cross-clause merging is introduced by this projection.
- Preserve `local`, `shared`, `collective` and `unresolved` semantics. A collective/range depth stays a joint fact rather than becoming an exact scalar for each place. Keep inventory facts distinguishable from observations. Preserve every graph fact/relation exactly once through the grouped or unassigned view; recognized locations with no linked facts remain visible in the mention list. An unresolved graph relation stays unresolved.
- Preserve time roles `onset`, `observation`, `report`, `publication`, `recession`, `clearance` and `unspecified`. Return saved publication metadata separately. Pass it to the context engine only if timezone-aware; otherwise pass null and explain that the timezone is unknown. Never assign a timezone to make it acceptable. No absolute-time or numeric-depth synthesis is added.

The existing `/candidates/{article_id}/extraction` preview also invokes placement and must not be reused as this endpoint's implementation. The legacy claim schema lacks `LOCAL_AREA` and has flood defaults, so do not coerce the context graph into that schema. `NewsExtractionRun` accepts only `rules_only`; do not record neural processing under that mode.

## Local runtime and controls

- Default `NEWS_NER_PREVIEW_ENABLED` to false. Allow execution only for `development`, `local` or `test`; production fails closed even if the flag is set. Document running the local API bound to loopback. Model/bundle paths and manifest hashes are operator configuration, never request parameters. Do not edit local secrets or enable the flag automatically.
- Use a new, inference-only worker with the already qualified local Linux image `sha256:a51ce2a6b0f19f382ce96bf63c265e060b37112098176c97c66c23e887794680` (Python 3.12, spaCy 3.7.5). Launch through an argument list without a shell, pulling, building or dependency installation. Docker Desktop's Linux engine is required; cloud packaging is deferred.
- Prepare an ignored private inference bundle by copying only the retained seed-0 checkpoint and the required pinned base tokenizer/vocabulary resources. Authenticate source manifests and exact file membership before copying; freeze a bundle manifest with relative paths, sizes and hashes. Preserve the originals. Keep weights and article evidence outside Git; the bundle must contain no corpus, references, expected answers, credentials or validation/holdout files.
- Promote copies of the v40 proposal function and the v41 dependency closure into an inference-only package under the backend service layer. Keep the frozen research files intact. Replace only their research import boundary with the equivalent standalone input validator and label constants. Record a source-to-runtime file manifest and require behavioral parity. Do not import study controllers, annotation/reference modules, training callbacks or the shadow worker's global ORM facade into the application.
- Reuse the qualified CPU inference loader behavior: load the serialized tokenizer/base vocabulary, override only its factory in memory, verify serialization and source-token reconstruction, load only the retained six-class NER pipeline, and prohibit initialization/training calls. The pipeline is exact body -> neural mentions -> unchanged v40 `combined` proposal view -> v41 context -> validated projection. Rule additions/retags retain their own provenance and never become neural predictions. No alternative recognizer or fallback runs on failure.
- Run one short-lived container per request: two CPUs, 4 GiB memory/swap cap, no network, read-only root/code/assets, dropped capabilities, no-new-privileges, PID limit 128, bounded 64 MiB tmpfs and single-thread numerical libraries. Send only the copied request as JSON over stdin; receive bounded JSON over stdout. Mount no repository root, database sockets, Docker socket, `.env`, references or expected answers inside the worker.
- Serialize requests across local API processes with an owned OS file lock, rejecting concurrent work rather than queuing. Enforce the existing 100,000-character body limit; reject rather than truncate/chunk. Allow at most 60 seconds for startup/model load and 30 seconds for extraction; enforce a 100-second host deadline including launch/cleanup overhead. New adapter performance must be measured; older timings are context, not a new SLA.
- Give each request an unpredictable owned container name and retain its ID. On success, failure, timeout or client cancellation, stop/remove only that owned container and verify termination before releasing the lock. Cleanup failure leaves the preview unavailable until ownership is reconciled; it never triggers a broad Docker cleanup or automatic inference retry. Do not log article text, raw worker stderr, private paths or secrets through public API errors.

## Errors and verification

Return stable error codes/messages through the API's existing `detail` convention: 404 `article_not_found`; 409 `article_body_unavailable` for missing/blank/error-marked capture; 413 `article_too_large`; 429 `preview_busy` or rate limit; 503 for disabled/environment/storage/runtime/assets/cleanup unavailability; 504 `preview_timeout`; 502 `preview_worker_failed` for crashes, malformed output or invalid bindings. Failures never appear as a successful empty extraction. Set no-store on error responses too. No automatic fetch, retry or rules substitution occurs.

Implementation is complete only after these checks:

1. **Frozen parity:** authenticate the v41 freeze and cached v40 bindings first. Runtime copies reproduce the saved v41 outputs for all 24 contextual inputs and all original/four cached proposal views, plus all 238 old context, 36 temporal and 36 new fixtures in their prescribed views. Preserve all oracles and three holds. The copied location proposal function matches its frozen behavior on the 36 fictional location cases; use cached mentions for context comparisons rather than re-recognizing real study texts. No re-scoring or reference revision is needed.
2. **Response meaning:** verify exact Unicode/repeated-occurrence offsets, body/input hashes, provenance separation, empty/unassigned fields, complete graph-to-projection accounting, distinct observations, collective/range/inventory handling, multiple clocks, publication with unknown timezone, rainfall/forecast/report counterexamples, and subsided/cleared evidence retention. A source slice or binding mismatch rejects the whole preview.
3. **API boundaries:** use a small test app with fake read-only article storage, without application startup jobs or shared database connections. Exercise unauthenticated/non-admin denial before inference, successful admin preview, every declared error, no-store, rate/concurrency limits, and verify no add/flush/commit, queue, fetch, placement, publication or routing call is made.
4. **Actual local adapter:** run the new endpoint/service with fake saved-article storage and real isolated inference on fixed fictional texts. Check pipeline identity, tokenizer reconstruction, controls and response bindings. Separately compare original neural spans on the six previously qualified training-only full articles against their saved spans, with source hashes frozen first. Expected spans stay outside the worker. This verifies adapter parity, not new accuracy.
5. **Lifecycle faults:** exercise missing/corrupt assets, unavailable Docker/image, malformed/oversized worker output, startup/extraction deadlines, crash, cancellation and lock contention; verify owned-container cleanup and no fallback/retry. Freeze the check workload before real adapter runs; retain failed receipts rather than silently reusing an attempt.
6. **Preservation and reporting:** verify frozen research/code/evidence hashes and existing historical/excluded metadata without reading validation/holdout content. Publish aggregate checks/runtime limitations under `docs/evaluations/`, keep raw evidence private, and update the task plan, progress, index, NER roadmap, operator guide and implemented API catalog truthfully. No test count or successful runtime connection is claimed before execution.
