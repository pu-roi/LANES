## Root cause and retained evidence

Article **47** already held a clean, original publisher reporting capture. A fresh bounded fetch through the configured GMA collector returns exactly the same **1,297 characters**, including the **September 9, 2026, 3:09 PM** update and the three listed Malabon/Marikina roads observed at **2:47 PM**. Publisher body SHA-256: `f5ff7d13e255ed82ab9c024bcd1aae02fee4ce5806c4a7411bc818e2f58ed763`.

The earlier [publisher-body investigation](news-publisher-body-capture-20261022/README.md) had identified version **137** as a **9:55 AM search-index snapshot wrapped in reconstructed HTML**, rather than retained original publisher HTML. It includes Google promotion/caption text and a different Quezon City list. Its **1,970-character** body hash is `a7b92b1ec22db882779dcc2d3f0d3dc153d834f325a00432a551d04357b57708`.

The pilot subsequently pinned that older body and copied it to compatible native version **574**, despite clean publisher versions **140/569** already existing. Raw NER **375** and correction **380** therefore processed the indexed body. Their checks established consistency with that input; they did not establish original-publisher capture provenance. The pilot should have stopped for source review. The modal then presented the run's input as unqualified “Full article text,” hiding the distinction from the current collected article. Gemini did not author or replace the displayed source text, and it was not fetching the live publisher page.

The current live [GMA publisher article](https://www.gmanetwork.com/news/topstories/metro/1001693/list-flooded-roads-in-metro-manila-wednesday-sept-9-2026/story/) matches the clean retained body byte for byte. This does not prove every earlier indexed observation false or authenticate the earlier body as original publisher HTML. No old source version, result or derived record has been overwritten to manufacture consistency.

The blue play symbols were literal Unicode `▶️` markers in the old captured body. React rendered plain text; there was no video/control behind them. Display formatting removes decorative line-start markers only, preserving the original bytes, offsets and hashes.

## Reader, processing and UI changes

- `news_source_read_service.py` compares the exact selected version with its own article's current collected body. Existing authenticated admin detail endpoints return additive read metadata for the current capture, separate selected-capture time and mismatch status. Missing/invalid ownership or evidence fails visibly. Reads never retrieve, extract or write.
- Source Article now shows the **current collected publisher capture**, its actual retrieval timestamp, and a clear warning when the selected observation came from a different input. It states that saved text can differ from later live updates. Processing History continues to show each run's exact immutable input under **Captured extraction input**; it never substitutes the current body for that evidence.
- Collection's default Article view opens the current saved article. Explicit history/event-run selection keeps its original version. “View current article” and “View latest extraction” switch these views explicitly.
- Flood Details uses the **selected observation's existing backend summary**: location/locality, raw reported depth, supported observation time, condition and passability. Missing fields remain unknown. Shared depths are explained without assigning per-road measured depth.
- Selected field-specific, exact saved quotations supply the supporting passage. The backend validates their offsets/text against the original run input and omits intervening page chrome; it does not rewrite source facts. Raw NER entities, offsets, group IDs and repair diagnostics remain in Processing History.
- The shared `RecordDetailsPanels` scroll dependency ships with the reader, preserving the flow dialog's scrolling and separate source/history panes on desktop and mobile. Existing modal/tabs/styling are retained.
- The manual pilot now rejects an intact but superseded/missing body with `pilot_source_capture_requires_review` before processing/outputs. The guard applies to the delegated GMA continuation/archive policies. Existing grants/receipts are preserved; no grant authorizes the clean source yet. General execution stays disabled. Normal scheduled RSS configuration is unchanged.
