## Delivered behavior

- **Moderation Center:** Fetch the existing full report detail rather than manufacturing a partial report from the moderation summary. Water level, submerged hazards, road coverage and passable vehicles use the same authoritative data as Spatial Operations, with existing missing-value handling. Re-read persisted report status before map navigation. Approved reports open Active Zones and resolve their linked zone/contributor; pending reports open Needs Review. Rejected reports retain the existing inspection-only workflow. Unavailable reports/zones surface an error. Only the redundant View on Map Focus action is disabled in this moderation dialog; Spatial Location's View on Map remains.
- **Owner notifications:** The developer explicitly chose entry into the existing pending queue as Under Review; there is no new staff-started review status. Pending creation and approval/link/rejection outcomes stage SYSTEM notifications in the existing transaction, with report ID, action and title in the existing JSON payload. Repeated status requests do not create a duplicate notice. Rejection reasons remain public to the owner; internal staff notes and complaint identities are excluded. Owner-only `GET /api/v1/reports/me/{report_id}` supports report notification details, and marking a notification read checks ownership before mutation. The bell retains unread behavior, visible errors and existing post-warning handling. The report-detail portal mounts only after client hydration and when details exist.
- **Homepage and chronology:** The developer chose active map zones created on today's UTC date for the daily flood statistic. The backend reuses active-zone expiry/configuration/simulation rules and counts each zone once, including official zones. The existing response field remains compatible. The homepage labels the daily UTC meaning, polls every minute, refreshes through existing SSE/flood synchronization and does not display a false zero on failure. Visitor telemetry is independent of the flood-stat query. Both Community tabs order by publication timestamp with ID tie-breaking.
- **Community filters:** Server-side sort, UTC/rolling dates, active/resolved lifecycle, existing severity and optional strict Nearby radii apply before counting and pagination. URL-backed controls, reset, cache isolation, empty/error handling and desktop/mobile layouts are covered in the [filter acceptance](community-feed-filters-20261011.md). Public feeds enforce approved/public/nonarchived linked-report visibility; authors retain authorized My Posts and detail access.
