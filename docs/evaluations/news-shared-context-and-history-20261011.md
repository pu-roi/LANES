## Numbered locality NLP repair

The developer subsequently requested general number-name matching rather than a single Sitio Sais alias. Research used [Oxnard College's Filipino number handout](https://www.oxnardcollege.edu/sites/oxnardcollege/files/media/pdf_document/2024/oc_-_fili_-_numbers.pdf), [Essential Tagalog Grammar: cardinal numbers](https://learningtagalog.com/grammar/other_describing_words/expressing_quantity_or_distribution/cardinal_numbers.html), [Diksiyonaryo: singko and beynte](https://diksiyonaryo.ph/search/beynte%20singko), [Diksiyonaryo: singkuwenta](https://diksiyonaryo.ph/search/singkuwenta), and [RAE's cardinal numeral table](https://www.rae.es/diccionario-estudiante/docs/numerales.pdf). These document native Filipino cardinals, Spanish-derived Filipino spellings, original Spanish forms, and compound-number/linker structure. Additional explicitly supported colloquial spellings are enumerated in code; unknown spelling is never guessed through fuzzy similarity.

`locality_number_service.py` now builds deterministic comparison keys for Sitio, Purok, Barangay/Brgy, Zone, Phase and Block followed by cardinals. It supports reviewed unit/teen/tens variants, compound tens, hundreds, thousands and millions within a bounded integer grammar below one billion. It handles accents, hyphens, apostrophe/curly-apostrophe `’t`, native `at`, Spanish `y`, joined forms, number markers and single-letter identifiers. This is not a claim of every regional language, arbitrary typo, ordinal, Roman numeral, range or fractional identifier being supported. Unsupported forms remain source text.

The Taglish extractor retains complete original numbered Sitio/Purok and other non-barangay locality mentions and their exact source offsets. A road's following numbered locality now keeps its full original compound form instead of truncating the first capitalized words. Barangay extraction/PSGC identity resolution retains its existing official-parent checks; number equivalence in placement comparisons does not invent a canonical barangay. Road/catalog/context comparisons use the same server-owned normalization. Full locality matching requires a complete recognized identifier, preventing `Purok 5-A`, `Purok 5/6` or `Purok 5 and 6` from matching `Purok 5`. Ordinary names such as Lima Street, depths and observation clocks are unaffected. No article, product label, catalog asset, coordinate or database record was rewritten; runtime processing requires no ChatGPT session for this normalization.

Pipeline identity advances to **v15** so later processing does not reuse a v14 extraction as if it used the repaired number matcher. Earlier saved runs, including the recorded local v14 map acceptance above, remain intact. This continuation does not rerun that historical simulation or restart the running local server.
