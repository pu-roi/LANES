## Frozen behavior contract

The [specification](../../plans/ner-interim-context-acceptance.md) distinguishes location recognition, depth/time recognition and fact association. It preserves raw qualifiers, ranges, roles, uncertainty and original Unicode offsets. Shared time does not imply shared depth; collective ranges do not imply one scalar everywhere. Observation is not onset, recession/subsidence is not clearance, parent places and shelters do not inherit road measurements, and indoor depth does not automatically replace broader street observations.

The **40 fictional cases** contain every combination of ten families × English/Taglish × supported/counterexample: row measurements, separate depths/shared time, shared depth, ranges/qualifiers, scope boundaries, forecasts, negation, historical updates, observation/onset and recession/clearance. They include repeated names, Unicode and all six location labels, including LOCAL_AREA. They remain software fixtures, not new corpus passages or training data.

The future offline adapter receives only unchanged text/hash, an opaque ID, supported publication metadata and authenticated location mentions. References stay separate. Source-exact raw evidence and resolved/unresolved links must be explicit. It must neither invent a gauge/instant/geographic identity nor hide failure behind another extractor. The existing production claim schema and `rules_only` database constraint remain unchanged.

The later repair task must pass all fictional **behavior** cases, preserve previously supported correct baseline associations and introduce zero incorrect resolved associations. Positive cases prevent an always-abstaining implementation from passing. At least one source-bound targeted correction is required before calling a method supported. The existing-rules baseline must be authenticated in that later task; raw v32 diagnostic fields alone are not a complete association oracle. These gates are frozen before repairs, not tested extraction outcomes from this preparation.
