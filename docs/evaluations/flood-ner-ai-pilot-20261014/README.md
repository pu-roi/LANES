## Review decisions and limitations

- **Compressed-road cases remain unresolved:** the Malabon/Valenzuela list contains ambiguous Maysan/Paso de blas/Rincon/Pasolo/Bypass names, and another MMDA list contains Sgt.River and compressed crossing names without explicit parent cities. These records retain proposed spans, complete=false and label-type adjudication holds; they cannot be counted as accepted training examples.
- **Raw spellings remain separate:** Mapagmahal Street's narrative Pinhayan parent and embedded-post Pinyahan parent retain their own source-supported mentions. No normalization, municipality/code assignment or definitive geographic identity was invented. Purok 9 keeps its reported Barangay Poblacion parent without borrowing Nabunturan from the separate Puroks 5–8 clause.
- **Scope is explicit:** the location profile covers six v1 place classes. Regional aggregates such as Metro Manila/Luzon/Bicol Region, hydrology such as Manila Bay, and organization-only geographic names are documented outside this pilot taxonomy. Complete=true means complete within that declared profile, not recognition of every possible geographic class. Broader taxonomy coverage still needs qualification before reporting general location accuracy.
- **Source mentions do not establish flooding:** Camarines Sur is a visit location in a regional access report; it is annotated as a province without assigning the unnamed regional flood/access fact to it. Unknown dates, vehicle classes and geographic identities stay unknown.
- **Contextual evidence remains draft:** source depth gauges and temporal expressions are preserved without invented scalars/calendar dates. A shared light-vehicle restriction and one source-supported local status update have relationship nodes. Other associations, status/access observations, depth point/range/collective roles and separate severity references are incomplete, so no full contextual annotation acceptance is claimed. Recession is not clearance.
- **Use-basis/grouping holds remain:** source captures retain unknown reuse, research-only admission and original provisional identities. AI annotation authorization does not itself supply a publisher reuse assessment or frozen event/syndication split groups.
- **Publisher coverage is narrow:** all twelve pilot articles are from GMA. Expand other publishers and missing address/negative cases before treating the pilot as representative of the planned corpus.

## Explicit annotation/export profiles

AnnotationRecord now has a backward-compatible annotation_profile field. Old records default to context-rich-v1, retaining the eight-label research contract. location-only-v1 accepts only ROAD, LANDMARK, LOCAL_AREA, BARANGAY, CITY and PROVINCE; it rejects depth/time entities and contextual fact/relationship payloads in that record. Context evidence lives in a separate rich record.

The existing export command requires an explicit --profile location-only-v1 for the location dataset. Mixed/wrong profiles are rejected before output. Manifests record the selected profile and its actual label vocabulary; no silent removal of rich annotations occurs. Source admission, accepted/complete review, tokenizer alignment, grouped train/dev/test identities and constructed-test protections remain enforced. This is tested serialization tooling, not a trained transformer or production model.
