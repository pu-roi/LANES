Example commands: npm run dev, curl localhost:3000/api, pytest tests/api/
Example boundaries: Modify routes, ask before schema changes

This are the things that i research about how to avoid things when vibe coding.

1. Environment and config blunders
- AI models frequently forget to map local .env variables into the actual deployment platform (e.g., Vercel, Render). Ensure all required APIs and keys are defined in your deployment dashboard.
- AI has a habit of putting Stripe keys or database URLs directly into the source code. Search your codebase for http://localhost, apikey, or secret before pushing to production.
- Local-Only Dependencies: Check that all packages and services used in your code actually exist and will install properly on your server's runtime (e.g., Node.js versions)

2. Security and database access
-  If you are using a backend-as-a-service like Supabase or Firebase, AI will often generate frontend code without enabling Row Level Security (RLS). Check that RLS is turned on and policies are explicitly written so users can only access their own data.
- IDOR (Insecure Direct Object Reference): AI frequently generates routes where a user ID or document ID is pulled directly from the URL (e.g., /api/user/123) without verifying that the logged-in user actually owns that data. Ensure server-side ownership checks are present on every resource.
- Client-Side Auth: The AI might handle authentication only in the React/frontend components, leaving API endpoints entirely unprotected. Every backend route must enforce session/permission verification.

3. Application Logic & Stability
- Swallowed Errors: AI loves to generate catch blocks that simply console.error(err) but give the user a success state. Ensure your app shows user-facing errors so deployment issues don't lead to "dead" screens.
- Missing CORS/CSRF configurations: If your frontend and backend live on different domains, verify your Cross-Origin Resource Sharing (CORS) setup so API requests aren't blocked post-deployment.
